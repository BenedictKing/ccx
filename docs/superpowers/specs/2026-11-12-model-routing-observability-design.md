# 网关模型调用分布设计

状态：设计稿，尚未实现。日期：2026-11-12。

本次交付：需求与数据口径、界面结构、实现阶段和验收标准。
配套线框图：[可交互 HTML](../../wireframes/model-routing-observability.html)，直接打开即可，所有数据均为示例。

## 1. 目标与范围

回答一个明确问题：在选定入口协议和时间范围内，客户端请求的模型被哪些渠道承接，经过网关重定向后，最终向上游发送了什么模型，各占多少。

- 范围覆盖六类入口：`messages`、`chat`、`responses`、`gemini`、`images`、`vectors`。
- “实际发送模型”始终指 CCX 出站请求中的模型字段；Gemini 对应出站路径中的模型标识。
- 只观测网关的模型映射、透传、视觉回退、模型降级以及重试切渠；不探测、推断或追踪上游内部重定向。
- 入口协议按客户端访问的端点分类；渠道服务类型作为独立属性，协议转换不会改变统计归属。
- 查看分布与明细均为只读，不发起模型测试、不修改配置、不触发调度、不改变亲和或熔断。
- 本轮仅设计文档与低保真线框，不实现管理接口、埋点、存储迁移或生产页面。

## 3. 页面与交互

入口建议：在现有协议页增加“渠道管理 / 模型调用分布”页内切换，沿用当前协议选择；既有流量统计与渠道管理保持原入口。

筛选区包含时间、请求模型、渠道、实际发送模型与计数口径。第一版时间为最近 1 小时、6 小时、24 小时和今日；明确显示实际起止时间与时区。暂不增加年度报表或导出。

汇总显示：客户端请求、成功请求、失败请求、取消请求、进行中请求、上游尝试、发生重试的请求数。状态以网关生命周期为准，不能只用 HTTP 200 判断流式请求成功。

提供两种待比较的信息结构，属于同一功能的布局备选，不要求生产环境同时维护两套页面：

| 方向 | 信息顺序 | 优点与取舍 |
| --- | --- | --- |
| A：流向优先（建议） | 汇总 → 三列流向 → 路径表 → 请求明细 | 容易理解流量去向；模型较多时需要搜索、筛选和路径表辅助 |
| B：表格优先 | 汇总 → 按请求模型分组的路径表 → 请求明细 | 适合高密度排查；总体分流关系需要阅读数字 |

流向的三列固定为“请求模型 → 渠道 → 实际发送模型”。每条关联展示次数、当前口径内占比，悬停与键盘聚焦能看到完整名称。重定向发生在选中渠道后，不能画成协议级统一映射。

默认口径为“成功请求去向”，每个成功请求只归入最终成功的一个路径；切换“全部上游尝试”后，失败、取消和进行中尝试分别标识，重试可多次计数。

点击节点或路径后联动过滤路径表与请求列表，保留筛选条件并提供清除入口。图中的相邻连线是聚合关系，完整三元组以路径表为准，不能通过共享渠道节点推断不存在的源到目标组合。

路径表列为：请求模型、渠道、实际发送模型、映射结果、次数、占比。名称始终可完整查看；直接透传与“命中规则但名称不变”需可区分。

请求列表每行对应一个客户端请求，展示终态、尝试次数及与当前筛选匹配的路径。点击“查看链路”打开详情：按顺序列出每次尝试的渠道、映射规则、出站模型、选择原因、结果及耗时。

窄屏按“筛选 → 汇总 → 路径卡片 → 请求 → 详情”纵向展示；复杂流向不压缩成难读的小图，改用同一组路径卡片。长名称换行；表格可在局部滚动。

## 4. 路由与统计语义

### 模型与规则

每次尝试分别保留：客户端原始模型 `requestedModel`、本轮输入模型 `effectiveModel`、渠道映射后模型 `mappedModel`、最终出站模型 `sentModel`。模型降级可能改变本轮输入，视觉回退等网关行为可能继续改变最终模型。

记录实际执行的变换步骤与原因，不根据当前配置重新计算历史；不从响应里的 `model` 反推请求出站模型。普通未变换请求的四个字段相同。

当前 `RedirectModelWithMatch` 的顺序为：精确匹配优先，其次按源字符串长度降序做包含匹配，未命中则透传；单次映射不递归。观测必须复用实际解析结果，不能在前端复制一套匹配器。等长规则的当前行为保持原样，记录实际命中的规则即可。

`mappingOutcome` 为 `unmatched`（未命中）、`matched_unchanged`（命中但未改名）、`changed`（映射改名）；`modelChanged` 独立表示最终发送模型是否不同于原始模型。视觉回退、模型降级独立记录，不能伪装成映射规则。

### 计数与时间

- 客户端请求数：入口接收的、已通过鉴权并进入代理处理的请求，按网关生成的逻辑请求 ID 去重；包含选渠前失败。
- 上游尝试数：实际进入出站执行边界的尝试，连接失败也计入；仅候选过滤、选择失败和请求构造失败不产生上游尝试。
- 重试请求数：上游尝试次数大于 1 的逻辑请求数；切渠请求数另按不同渠道数大于 1 计算。
- 请求终态互斥：成功、失败、取消；未结束为进行中。客户端断开与流式中断按网关终态单独记录，不归入成功。
- 时间窗口按逻辑请求接收时间归属；其全部尝试随同请求纳入，避免跨窗口重试把一个请求拆开。长请求在结束前会更新当前窗口结果。
- 图的成功口径只计最终成功路径，分母为筛选内成功请求数；尝试口径按尝试计数，分母为筛选内全部上游尝试数，取消与在途均可见。
- 模型筛选始终匹配原始模型；渠道和目标模型筛选在尝试层匹配，三个条件必须命中同一次尝试。成功口径只匹配最终成功尝试。
- 全部尝试口径的汇总包含至少一次匹配尝试的逻辑请求，列表仍按逻辑请求去重；无尝试请求只在没有渠道或目标模型过滤时纳入汇总。
- 汇总中的上游尝试与重试数覆盖匹配请求的完整链路；路径图只计符合当前筛选的尝试。例如筛选备用渠道后，汇总仍可包含这些请求此前在主渠道的失败尝试，页面明确提示两者范围。
- 拒绝在两个口径之间复用占比。图外单列无上游尝试的失败请求，不能捏造渠道、模型和连线来补齐流量。

## 5. 观测数据设计

以下为实现阶段的建议模型，本轮不创建表、不执行迁移。

| 实体 | 主要字段 | 用途 |
| --- | --- | --- |
| 逻辑请求 | `gatewayRequestId`、`apiType`、`requestedModel`、`operation`、`requestSource`、`receivedAt`、`completedAt`、`status`、`failureStage` | 请求级去重、无渠道失败与最终结果 |
| 上游尝试 | `attemptId`、`gatewayRequestId`、`sequence`、四层模型字段、`startedAt`、`completedAt`、`status` | 同 Key 重试、换 Key、换 URL、换渠道均独立记录 |
| 渠道快照 | `channelUid`、`channelNameAtCall`、`serviceTypeAtCall`、`configRevision` | 历史归属、协议转换提示；不能用现时渠道索引重建 |
| 变换快照 | 映射是否命中、实际命中的源与目标、匹配类型、`mappingOutcome`、有序 `transformSteps` | 解释精确/包含匹配、透传、视觉回退与模型降级 |
| 调度摘要 | 选择原因、受限长度的跳过摘要、尝试触发原因 | 解释首次分配与后续切换，不存无限扩张的完整 trace |

逻辑请求 ID 由网关在代理入口生成，所有重试共享；尝试 ID 可以复用当前日志 ID，但必须显式关联逻辑请求。请求构造失败可在请求详情记录失败阶段，不构造“已发送”的尝试。

最终出站模型必须在发送前从实际构造结果提取，覆盖各处理器与网关内回退路径。记录顺序为创建请求、准备模型与渠道快照、开始尝试、更新尝试、完成请求；所有终结路径应幂等。

建议增加只用于身份识别的内部 `channelUid`：已有渠道一次性补齐、重排与改名保留、复制和新建生成新值；手工配置缺失或重复时校验并归一化。该身份不参与优先级、亲和或限流计算。

历史按“稳定渠道身份 + 调用时名称”显示，改名后可列出历史名；删除渠道仍保留历史并标记“已删除”。具有相同 BaseURL、Key 或名称的两个配置不可自动合并。

复用现有 SQLite 文件与写入机制，观测采用独立请求/尝试表和明确版本迁移，避免改变既有指标语义。请求、尝试写入与终态更新需有唯一约束及关联一致性；保留期复用指标配置，按请求及其关联尝试清理。

仅记录标识与必要的调度/模型元信息；不存提示词、响应正文、API Key、Authorization、带查询参数的 URL。现有日志若显示脱敏 Key，不成为新聚合维度。

观测失败不阻断代理；写入失败或队列丢弃必须暴露覆盖状态和丢失计数。崩溃遗留在途记录在启动后标记为“结果未知”，不能补写成功或普通失败；未知结果独立计数。

## 6. 查询接口与聚合

建议放在现有管理鉴权下，以下端点均为待实现接口：

```http
GET /api/{type}/models/routing?from=...&to=...&basis=successful_requests
GET /api/{type}/models/routing/requests?from=...&to=...&basis=all_attempts&cursor=...
GET /api/{type}/models/routing/requests/{gatewayRequestId}
```

`type` 为六类入口之一。共同筛选参数为 `requestedModel`、`channelUid`、`sentModel`；默认 `requestSource=proxy`，能力测试、渠道发现与后台探测不混入业务分布。第一版不提供混合来源开关。

聚合响应包含：`summary`、`paths`、`coverage`、`asOf`、规范化后的筛选。路径包含原始模型、稳定渠道身份与名称快照、最终模型、映射结果计数、次数和当前分母内占比；同一路径可以混有不同规则版本，详情保留各自快照。

列表返回每个逻辑请求的一行摘要、匹配尝试数、总尝试数和最终结果；详情返回原始模型、所有有序尝试与无尝试失败原因。响应严格按入口协议隔离，跨协议 ID 不能读取。

首屏汇总、图和列表在同一读事务内计算；`asOf` 固定请求接收时间上界，分页游标绑定筛选与上界，按“接收时间 + 请求 ID”做键集分页，新增请求不插入当前翻页结果。进行中请求的终态变化在刷新时体现；不承诺跨查询冻结数据库状态，也不在打开的详情内自动重排。

所有计数由后端同一套谓词计算；前端不以最近 50 条日志充当统计样本。结果按次数降序；图超过 12 条路径时只绘制前 12 条并显示“另 N 条”，分母仍为全部筛选结果，路径表通过分页查看完整结果，不伪造“其他模型”的流向。

第一版使用现有保留期内的请求/尝试记录直接聚合，按入口协议、接收时间和关联 ID 建索引。先验证 24 小时查询；跨月查询与预聚合留待真实数据规模证明需要后再做。

## 7. 空态、历史与特殊情况

- 全新实例：显示“此时间段暂无调用”，保留筛选；有配置而无请求，不展示伪流量。
- 筛选无匹配：明确显示当前条件和清除筛选入口；图、表与汇总同步。
- 升级前历史：标记“完整链路记录始于某时”，旧指标仍可在原流量统计查看；不得利用当前映射回填旧请求。
- 观测不完整：显示覆盖起点、遗留未知结果与写入丢失信息；已有完整记录可查看，不能宣称是完整分布。
- 重命名、删除、重排及规则热更新：使用调用时快照；一个在途请求的不同尝试允许有不同配置版本。
- 同名目标模型来自多个渠道：目标层可以合并模型名称，渠道层保持独立；完整三元组保留，避免误读合并路径。
- 无模型或解析失败：显示“未解析模型”，成功流向不出现；按失败阶段查看，不把空字符串视为某个真实模型。
- Images 按 `operation` 标注生成/编辑/变体；Vectors 仍执行既有 embedding 兼容性边界。本功能不增加这两类的 capability-test。
- 网关模型降级与视觉回退：详情展示实际发生的完整步骤，分布取最终出站模型；只发生候选过滤不产生调用连线。
- Compact 等网关内部辅助调用：通过调用角色关联到入口请求，单列“内部辅助调用”，不参与默认代理尝试及成功去向的分母，避免一个成功请求有多个“最终去向”。第一版详情可展示其模型与结果，不增加独立仪表盘。

## 8. 实施阶段与回滚

1. **语义与样例固化**：确认本稿及 A/B 信息结构；把重试、改名、无候选和模型回退样例固化为验收数据。
2. **身份与观测记录**：增加逻辑请求关联、内部渠道身份、配置/模型快照与独立存储；覆盖全部六类处理器及内部回退路径，建立失效可观测性。
3. **只读聚合 API**：完成时间归属、两套口径、共同筛选、分页和覆盖提示；用手算样例核对图表与汇总。
4. **协议页功能**：复用现有协议选择、管理鉴权、语言资源和主题，落地选定布局、路径联动及请求详情。
5. **回归与发布**：先在隔离测试实例验证真实出站模型与记录一致，再验证长流式、取消、重启、热更新和六类入口隔离。

依赖顺序为 1 → 2 → 3 → 4 → 5；只画页面而缺少请求级关联与历史快照，不能算功能完成。

兼容性要求：代理响应格式、模型改写行为、渠道顺序、亲和、重试预算、Key 池和既有统计均保持原语义。数据库迁移采用增量方式；历史记录不强制补齐未知维度。

回滚方案：关闭新页面及观测写入开关，保留新增只读历史表；旧版本继续读取旧指标表。渠道新增身份字段需验证旧版本兼容及旧版本保存配置后的重新补齐行为；不依赖删除表或回退数据库版本。

本轮不执行以上实施步骤，不迁移任何运行数据库，不修改运行配置。验证与预览不停止、不重启现有网关实例。

## 9. 验收标准

| 场景 | 必须满足的结果 |
| --- | --- |
| 单请求直接透传 | 1 个请求、1 次尝试；显示未命中、模型不变 |
| 精确/包含/未命中/同名映射 | 与后端实际匹配一致；同名映射不误标为改名 |
| 同渠换 Key/URL 后成功 | 1 个成功请求、2 次尝试；不误标为切渠 |
| 首渠失败、备渠成功 | 1 个成功请求、2 次尝试；成功去向只计备渠，全部尝试计两条 |
| 所有渠道失败 | 1 个失败请求、N 次尝试；成功图为零 |
| 无渠道或构造失败 | 请求失败且保留原因；上游尝试为零 |
| 请求跨时间边界重试 | 按入口时间归属，链路完整，汇总与分页不重复 |
| HTTP 200 后流中断/取消 | 保留真实终态，不当作成功 |
| 网关视觉回退/模型降级 | 每轮输入、映射后和最终出站模型可区分 |
| 内部 compact 辅助调用 | 不增加默认成功路径与代理尝试分母；详情可追溯 |
| 渠道改名、删除、重排/映射变更 | 旧记录保持调用时归属与规则，当前配置不覆盖历史 |
| 相同 URL/Key 的两个渠道 | 按内部渠道身份区分，不共享分配计数 |
| 协议转换与六类入口 | 入口隔离；出站模型/路径与本地假上游实际收到的一致 |
| 能力测试、发现与后台探测 | 不进入默认业务计数 |
| 重启、部分观测失败 | 完整历史可查；未知和缺失被标记，无伪造完整率 |
| 长名称、键盘与窄屏 | 名称完整可见；可操作筛选、路径选择、详情开关；无页面横向溢出 |
