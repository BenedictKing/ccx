# 2.9 数据隔离升级演练

## 范围与来源

- 目标分支：`codex/v3-lean-from-2.9.37`；只演练 2.9 六协议数据，不迁移 3.0 `channelsV3`。
- 来源：2026-07-09 的 `config.json.bak-before-autopilot-*` 历史备份，六协议数组格式，无 3.0 权威渠道标记。它比 `v2.9.37` tag 晚两天，不能声称是发布包直接导出的样本。
- 指标库补充样本：2026-05-24 的 Desktop `metrics.db`，schema version 3，与 `v2.9.37` 指标存储代码的版本一致；日期更早，不能与 7 月配置视作一组数据。
- 在 worktree 忽略目录 `.config/upgrade-rehearsal-20261105/` 留存私有来源副本；权限 `0700`/`0600`，不纳入 Git。测试只加载临时副本，未启动服务或调用上游 API。

## 结果

| 检查 | 结果 |
| --- | --- |
| 六协议渠道 | 386 个，加载、保存、重启与原快照顺序一致；缺省的 vectors 数组按空数组处理 |
| Key 与模型映射 | 431 个可用 Key、92 个禁用 Key、570 条映射；原有值保持一致 |
| 配置字段 | 原快照所有非空渠道字段及全局设置逐项比较；允许既有迁移补充映射，不允许覆盖已有映射 |
| 回退 | 升级保存产生备份；在隔离目录回放原始快照后可再次加载；来源文件字节未变 |
| 指标库结构 | 旧 schema 3 可由精简版打开；`request_records` 与 `circuit_states` 记录数在关闭、重启后不变，源库字节未变 |
| 3.0 格式防护 | `channelsV3`/`channelAuthoritativeVersion` 被拒绝加载，原文件不改写（独立回归测试） |

## 尚未覆盖

- 没有找到与 7 月配置同一时点的指标库。另一份 Desktop 库已是 schema version 9，不能当作 2.9 数据；5 月的 schema 3 样本只证明旧库结构可读和记录可保留，不能证明同一用户全量数据的一致性。
- 没有找到同期 2.9 Desktop 配置状态快照。Desktop 配置读写与目录解析代码相对 tag 未改动；未把当前 3.0 客户端状态当作旧版验收样本。
- 未对实际使用中的目录或生产站点运行精简版。发布前还需安装包升级和回退验证。

演练入口：`CCX_UPGRADE_SNAPSHOT_CONFIG=/path/to/private/config.json go test ./internal/config -run '^TestLegacyConfigSnapshotUpgrade$' -count=1`；指标库用 `CCX_UPGRADE_METRICS_SNAPSHOT=/path/to/private/metrics.db go test ./internal/metrics -run '^TestLegacyMetricsSnapshotUpgrade$' -count=1`。断言失败不回显 Key 或请求内容。
