# 网关模型去向实施与验证

范围：延续 2026-11-12 的已确认设计，只观测网关；保留用户完善的线框，以协议全局统计下方的流向图与明细侧栏实现，不提供表格视图。

## 阶段与依赖

1. 渠道身份：补齐内部 UID，创建/复制生成新身份，改名与重排保持身份。
2. 请求观测：鉴权后生成逻辑请求，每次实际出站执行单独记录；捕获构造后的模型、映射规则和终态。
3. 存储与 API：独立 SQLite 快照、异步持久化、24 小时窗口、协议隔离、两种计数口径与键集分页。
4. 前端融合：共享全局统计时间和刷新；按需展开，节点筛选、路径明细、移动端路径卡片。
5. 验证：定向测试 → 全量测试/竞态 → 构建 → 隔离实例与浏览器。

顺序为 1 → 2 → 3 → 4 → 5；观测不修改亲和、限流、熔断及既有指标语义。

## 实施决策

- 复用现有 SQLite 连接，以独立 `routing_records_v1` 表保存逻辑请求与尝试的原子 JSON 快照；不占用原指标表的 schema 版本。
- 内存查询窗口最多 24 小时、最多 50,000 个请求；触及容量或丢失写入时返回覆盖不完整标志。持久化按现有指标保留期清理，重启加载最近窗口。
- 不记录提示词、正文、密钥或上游 URL；只存模型、渠道身份、规则和必要的调用元数据。
- compact 辅助调用保留在请求详情，排除默认代理分母。
- Responses 原生 WebSocket 按 `response.create` 单独关联请求与终态事件；忽略预热，复用连接不合并逻辑请求，HTTP/SSE bridge 沿用 HTTP 观测。
- 新区块跟随现有统计容器卸载，收起后停止观测查询；长时间范围只提示支持边界，不影响原趋势。
- 主分支与当前精简分支已分叉，不能 ff-only 同步；在当前精简版上实施，不混入主分支 3.0 架构。
- 依赖已在当前 worktree 就绪；验证实例使用临时数据目录、动态空闲端口及本地假上游。

## 验证重点

- 六协议实际出站模型与记录一致；首次失败后重试成功为 1 个请求、2 次尝试。
- 精确/包含/同名映射、模型回退、视觉回退，不能根据响应或当前配置回推历史。
- HTTP 200 后流处理失败、客户端取消、崩溃遗留未知结果。
- 共享 URL/Key 渠道不合并；旧配置补齐 UID 后可保存与重启。
- 成功口径不含失败路径；全部尝试口径的组合筛选必须命中同一次尝试。
- 游标与协议/筛选绑定；跨协议详情不可读取。
- 浏览器验证节点筛选、路径下钻、两次尝试明细、时间共享、范围提示及手机无横向溢出。
- 原生 WebSocket 连续调用、乱序响应 ID 关联、失败与客户端关闭，以及预热不计数。

## 兼容与回滚

代理接口与旧统计继续使用现有数据结构。回滚旧二进制时忽略新增渠道身份字段与观测表；保留数据库，旧指标不受影响。重新升级会补齐缺失身份。

不停止、不重启现有运行实例；代码生效由用户按现有流程手动重启。
