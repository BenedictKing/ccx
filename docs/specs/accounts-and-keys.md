# 站点账号、分组与 Key 生命周期

> 状态：现行规格
> 代码基线：`53b79829`

## 1. 目标与范围

站点接入把 new-api/sub2api 家族账号的管理凭证、分组、推理 Key 和 CCX 四文本渠道建立可追踪关联，并持续同步远端状态与倍率。Key 生命周期同时覆盖手工渠道和托管渠道。

- 协议级 provisioning 仅支持 `messages`、`chat`、`responses`、`gemini`，各协议的配置、Key、分组和证据独立。
- 支持管理令牌接入与仅推理 Key 导入；支持已有渠道绑定/解绑账号、已有远端 Key 复用和明确模型序列。
- 对账以远端 Token ID、账号/分组归属和本地 Key 指纹定位，不能按可改名称跨账号合并。
- 管理面信息验证、真实推理验证和实际业务成功构成不同证据等级，探针失败不等于推理不可用。

非目标：不代办站点登录、验证码或 2FA，不保证所有 new-api fork/sub2api 版本接口一致，不因账号删除自动删除远端 Key 或本地业务渠道，不为 Images/Vectors 做协议接入。

## 2. 页面与接入契约

Web/Desktop 的站点接入使用同一 `/api/siteaccess/*` 契约。接入向导固定为四步：

1. **站点**：选择 newapi/sub2api、管理令牌或仅推理 Key，输入规范化后的站点地址和凭证；验证失败给警告但可按当前能力继续，不伪装已验证。
2. **协议与分组**：选择单一协议、Agent、分组/排除组、倍率上限、已有远端 Key 和是否自动补接新分组；先选模型再按目标模型筛选分组。
3. **模型**：显式选择主模型/备用模型及映射；无模型目录时允许人工输入，映射目标必须属于已选模型。
4. **验收**：展示逐组创建/复用/跳过结果和证据，可主动执行最小真实请求或立即对账；失败显示诊断且不阻断已保存配置。

账号列表展示脱敏令牌、站点身份、余额/信息（适配器支持时）、证据、最近同步时间和错误；编辑凭证保留 UID、托管记录、计划和证据。账号身份冲突必须要求单独接入，不合并同站点不同用户。

渠道编辑中的账号绑定区允许选择账号、远端分组和匹配的已有 Key：绑定只更新归属与可信倍率，不隐式创建/删除 Key；解绑保留渠道及推理配置。所有创建、验证和对账按钮具有加载、防重复、错误和部分成功状态，窄屏步骤标题可读。

## 3. 账号、分组与倍率运行逻辑

### 接入与幂等

- 账号 UID 优先由站点类型、规范化 BaseURL 和用户身份派生；未识别用户才以令牌指纹兜底。换令牌不换身份，同站点多账号不串绑。
- Provisioning 在账号级操作锁内串行，逐组校验倍率上限和目标模型；`maxMultiplier=nil` 不限，0 只允许零倍率，未知倍率不得当成零成本。
- 渠道采用 `ccx: host / protocol / group` 稳定命名并幂等 upsert；远端 Key 按协议、分组和模型集合确定名称，已有 Key 可复用并标记 Imported。
- 本地渠道保存失败时，仅回收本次新建且归属明确的远端 Key；复用的已有 Key 不删除。账号 Patch 与业务证据写入不能相互覆盖。
- 显式模型 fallback 保存用户模型顺序和预算，沿用普通调度硬约束；上游已提交正常响应后不再跨模型重试。

### 对账与证据

- 后台默认每 1 小时对账，间隔硬下限 30 分钟，单轮上下文超时 2 分钟；单账号失败不中断其他账号。
- 对账读取完整远端 Token 和分组倍率。远端明确删除才按 Token ID/归属/指纹停用本地 Key；查询失败保留最近可信状态，不把管理面失败当成推理失败。
- 远端停用、过期、分组缺失和倍率变化同步到 Key 配置；本地已删除对象标记 `missing_local`，不自动复活人工删除或排除对象。
- 只有账号显式启用 `autoSyncGroups` 时，才为符合原计划的新分组补建 Key/渠道。
- 证据按协议+分组记录：`configured` → `info_verified` → `real_request`，等级只升不降；失败只更新诊断，真实业务成功也可升级为真实请求证据。

## 4. Key 状态、限制与恢复

- `apiKeys` 是当前可轮换 Key，`apiKeyConfigs` 保存名称、启用状态、quota group、倍率、远端身份、限速、权重和模型限制；`historicalApiKeys` 只用于历史统计聚合。
- 手动暂停与自动拉黑均从可用池排除，但来源、原因和操作记录不同；恢复必须保留 Key 配置快照，不能重复添加或丢失 quota group。
- 鉴权/权限/余额可禁用整 Key；模型不存在等确定性错误优先限制 `(Key,实际模型)`，不影响该 Key 的其他模型。人工还可禁用 `(quotaGroup,模型)`。
- `disabledKeyModels` 默认有自动恢复时间；定时任务到期清理。整 Key 自动恢复只针对允许的原因，遵循 recoverAt 和最小禁用时间，详见调度规格。
- 远端 `remote_token_deleted` 通过对账确认后停用；管理面临时查询失败不得拉黑。远端状态恢复与人工恢复均需按来源语义处理，不自动复活已删除本地对象。
- Key 置顶/置底只改变轮换顺序；删除 Key 不删除历史指标和请求记录。最后一把 Key 被禁用后渠道可无 Key suspended，合格 Key 恢复时可重新激活。
- Key 操作记录覆盖手动暂停、启用、恢复、自动拉黑和定时恢复，记录结果包括保存失败；失败记录不表示磁盘配置已回滚。

## 5. 持久化、安全与异常边界

- `site_accounts.json` 位于配置文件同目录，原子写入。管理令牌以 AES-256-GCM 加密并带 `$enc$` 前缀；旧明文仅作读取兼容。
- 密钥优先来自 `CCX_SECRET_KEY`，未设置时按 hostname/GOOS/GOARCH 派生。生产应显式配置并备份；更换密钥或机器派生身份可能导致旧令牌无法解密。
- 账号存储不持久化推理 Key 明文，只保存 16 hex 指纹、Token ID、协议、分组和 Imported 标记；明文仅在创建/导入时写入目标渠道。
- 管理 API 只返回令牌尾部 4 位；日志、证据和错误摘要不得包含完整管理令牌、推理 Key、Authorization 或站点敏感响应。
- 账号删除只删除本地账号托管记录，不隐式删除远端资源；渠道解绑不删除渠道或 Key。执行远端创建/回收必须限定本次明确归属的资源。
- 管理面适配器遇到不兼容接口、HTML 错误或分页不完整时返回诊断，不能据此宣称远端 Key 已删除或余额准确。
- 余额只读展示，不参与调度，也不作为站点总成本的权威真相；倍率上限是调度准入约束，不替代真实账单。
- 配置保存与账号元数据更新可能分属两个存储，失败必须返回真实结果并保留诊断，不能展示跨存储“全成功”假象。

## 6. 验收标准

| 场景             | 必须结果                                                                       |
| ---------------- | ------------------------------------------------------------------------------ |
| 新接入与换令牌   | UID 稳定，证据/计划/托管记录保留；同站点多账号及身份冲突不串绑。               |
| 多协议多分组     | 每次只写选定协议；倍率/模型不合格组跳过，结果含复用、创建和跳过原因。          |
| 保存失败补偿     | 只回收本次新建远端 Key，已有 Key 与人工渠道不受影响，无半成功展示。            |
| 对账状态         | 远端明确删除才停用；临时查询失败不改状态；本地删除不复活，新分组仅授权后补接。 |
| 证据等级         | configured/info_verified/real_request 只升不降，失败保留诊断，真实流量可升级。 |
| Key×模型与整 Key | 模型缺失只限制组合，鉴权/余额按整 Key；恢复保留配置并遵守时间。                |
| 凭证存储         | 磁盘管理令牌加密、推理 Key 不明文入账号库、API 仅脱敏，旧密文解密失败有诊断。  |
| Web/Desktop 闭环 | 四步向导、已有 Key、绑定/解绑、真实验证和对账均展示真实后端结果。              |

验收使用假站点覆盖 new-api/sub2api 契约、分页、并发和远端变化；真实站点、完整 Wails 和签名安装包验证单独记录，不由 mock 结果替代。
