# CCX 现行特性规格

本目录是 CCX **当前产品行为与设计实现的单一事实源**。规格描述应实现和已实现的契约，不代替面向用户的使用教程，也不把历史方案或未来设想当作现状。

当前核对基线：`53b79829`。每份规格包含正常流程、界面或 API 契约、状态与异常、持久化/安全边界、验收标准及代码测试索引。

## 特性域

1. [协议网关与转换](protocol-gateway.md)：六协议入口、原生透传、跨协议转换、流式、WebSocket 和 compact。
2. [渠道配置与模型能力](channels-and-models.md)：渠道字段、模型映射、能力、渠道发现和连通性测试。
3. [调度、故障转移与运行保护](scheduling-and-resilience.md)：选择顺序、重试预算、熔断、限速和定时恢复。
4. [会话续接与子代理路由](sessions-and-subagents.md)：Responses 会话、加密续聊、成功来源、thinking 和独立子代理池。
5. [站点账号、分组与 Key 生命周期](accounts-and-keys.md)：站点接入、倍率、对账、证据及 Key 状态恢复。
6. [可观测性、请求历史与用量报表](observability-and-reporting.md)：指标、模型去向、历史、Key 运维、诊断和 CSV。
7. [Web、Desktop 与客户端接入](management-and-clients.md)：页面契约、本地服务、Agent 配置和客户端行为。
8. [部署、配置、数据与安全](deployment-and-data.md)：运行时路径、认证、TLS、持久化、备份、升级和回滚。

## 同步约定

- 新需求或行为变化先修改对应规格，再修改代码和测试；同一交付中回写实际实现差异、未验证项和代码索引。
- 纯重构、测试补充或不改变行为的文档修正可不先改规格；发现规格与代码冲突时，先确认预期行为，不得静默选择一边。
- 界面需求必须覆盖加载、空态、错误、权限、并发、未保存和窄屏；运行需求必须覆盖重试、并发、幂等、持久化和安全边界。
- 未实施内容放入明确的设计/计划文档，不在本目录标记为现行。日期计划保留在 `docs/superpowers/`，其内容仅作历史背景。
- 用户教程位于 `docs/guide/`、`docs/providers/`；架构摘要保持概览并链接本目录，避免复制详细规则。

## 文档验收

提交前检查规格内相对链接、占位符、Markdown 结构和代码入口；涉及行为变更时同时运行对应后端/前端测试与构建。纯文档变更至少执行文档站构建，不声称完成代码或真实上游验证。
