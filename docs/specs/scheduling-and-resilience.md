# 调度、故障转移与运行保护

> 状态：现行规格
> 代码基线：`53b79829`

## 1. 目标与范围

调度器在六类独立渠道池中，按用户显式意图、模型硬约束、运行健康和持久顺序选择上游，并在一次请求的预算内完成 URL、Key、渠道或显式模型序列的故障转移。

- 硬约束优先于偏好：鉴权、路由前缀、模型支持、上下文/输出、视觉、Embedding、子代理参与和显式渠道限制不得被优先级或亲和绕过。
- 普通调度是确定性规则，不根据提示词内容自动评判质量、成本或任务难度。
- 运行保护包括指标熔断、half-open 探测、主动限速、响应头冷却、负载软跳过和定时 Key 恢复。
- 本文定义跨协议共用规则；协议提交边界见[协议规格](protocol-gateway.md)，子代理独立池见[会话规格](sessions-and-subagents.md)。

非目标：不承诺所有失败都可重试，不在响应已经提交后拼接另一上游，不通过关闭熔断绕过鉴权、余额、人工暂停或限速。

## 2. 渠道状态与配置契约

| 配置                     | 现行语义                                                                                                                         |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| `status`                 | `active` 参与普通调度；`suspended` 暂停；`disabled` 为备用池，不参与普通请求。共享的鉴权、Key 和运行保护状态不因界面展示而消失。 |
| `priority`               | 数字越小越优先；未显式设置时按当前索引/归一化结果排序。拖拽排序持久修改顺序，不等于 Promotion。                                  |
| `promotionUntil`         | 有效期内的普通渠道临时优先，可绕过自动健康检查尝试一次；受 Key、运行 cooldown 和硬约束限制。                                     |
| `X-Channel`              | 按渠道名称显式指定；仍需通过模型、前缀、上下文、子代理参与及本次失败检查，不自动换到别的渠道。                                   |
| `modelFallbackPolicies`  | 用户显式配置请求模型、顺序、最大尝试和重试窗口；不是按内容智能选模。                                                             |
| `circuitBreakerDisabled` | 仅关闭该渠道自动熔断过滤，不关闭鉴权/余额拉黑、人工状态、模型约束或限速 cooldown。                                               |
| 限速字段                 | RPM 和最大并发为 0 表示不限；窗口 JSON 名保留 `rateLimitWindowMinutes`，当前值按秒解释；可显式启用响应头冷却。                   |
| 流式超时                 | 渠道值 0 继承全局，-1 禁用，正数覆盖；全局默认首内容 90 秒、活动空闲 90 秒、工具调用空闲 300 秒。                                |

- 未配置环境或调校台时，全局熔断默认滑动窗口 20、失败率阈值 70%、连续可重试失败阈值 5；调校台保存的 `circuitBreaker` 优先于同名环境兜底。
- 非流式请求和响应头超时支持全局及渠道覆盖；流式请求由响应头和流式健康字段控制，不能套用非流式总超时。
- 管理界面的状态、排序、Promotion、Resume 和调校台必须展示保存后真实配置；保存失败不得假装运行状态已改变。

## 3. 候选过滤与选择顺序

每次选择使用同一请求的配置快照，顺序如下：

1. **状态与模型**：过滤普通禁用、未激活策略和不支持有效请求模型的渠道，按 priority 或子代理序列排序。
2. **路由前缀**：有前缀只保留精确匹配渠道；无前缀排除所有配置前缀的渠道。
3. **上下文与能力**：校验输入窗口、显式输出、视觉和协议特定候选过滤；Vectors 再执行 Embedding 兼容过滤。
4. **显式渠道**：`X-Channel` 在硬约束后的集合内精确命中，不享有绕过权。
5. **Promotion**：普通请求优先尝试促销渠道；子代理独立策略禁用普通 Promotion。
6. **Trace/成功来源亲和**：主、子角色使用不同亲和键；普通亲和会让位给数字更小且健康的候选，加密续轮以来源兼容为先。
7. **普通 priority**：跳过本次已失败、非 active、无 Key、open/不健康、运行 cooldown 和负载软跳过的渠道，选择第一个合格项。
8. **压力与降级**：低水位候选不可用时允许高水位渠道兜底；健康候选均不可用时按当前降级规则选择失败率较低的候选并记录原因。

- 限流水位达到 50% 进入软跳过；降到 30% 以下并持续 5 分钟后恢复。文本请求可在普通文本池压力达到当前阈值时保留视觉渠道，避免占满图片能力。
- 选择诊断是 dry-run，不更新 lastSelected 或 override TTL；实际历史必须从请求观测读取，不能用当前配置重放冒充历史。
- 模型 fallback 策略按用户顺序逐目标执行；显式 `X-Channel`、激活的子代理默认模型或加密来源保护会禁用普通模型候选链，防止重试改回主模型。

## 4. 重试、熔断与限速运行逻辑

### 请求预算与故障转移

- 显式模型 fallback 策略的非法/缺省预算归一为最多 6 次上游尝试、90 秒；允许配置上限为 30 次、300 秒。预算被该请求的所有目标和尝试共享，在实际出站前消费。
- 未配置显式模型策略时沿用各协议渠道、URL、Key 循环，不虚构统一的 6 次/90 秒默认。
- 已消费预算但请求构造未进入上游时不计为上游尝试；观测、预算和日志对“尝试”的定义必须分别保持一致。
- 短空响应允许当前实现的快速重试窗口；其他可重试错误按分类换 Key、URL 或渠道。客户端取消、确定性的请求错误及已提交响应不进入无界重试。

### 熔断与探测

- 指标按协议隔离，并按 BaseURL、Key、serviceType 身份记录；失败率达到窗口阈值或连续可重试失败达到阈值可进入 open。
- open 到期后进入 half-open，只有获得探针资格的请求可验证；成功达到恢复目标后 closed，失败重新 open 并退避。
- 渠道聚合状态由各 URL/Key 状态形成；`circuitBreakerDisabled` 只把自动渠道熔断视为 closed，其他硬限制继续执行。
- 熔断状态在 SQLite 可用时持久化，启动恢复；指标持久化失败可降级内存模式并暴露诊断。

### 主动限速与冷却

- 渠道/Key 或 quota scope 可使用滑动窗口和并发信号量；排队超过允许等待或处于 cooldown 时快速 failover。
- `rateLimitAutoFromHeaders=true` 时解析 `Retry-After`、Anthropic 和 OpenAI reset/remaining 头。429 和剩余额度耗尽只冷却实际使用的 Key 或显式共享的 quota group，其他 Key 仍按渠道总限速尝试；5xx 退避保留渠道作用域。
- 冷却只延长不缩短，最多到当前时间后 1 小时；热更新配置保留已有 cooldown 和运行令牌。

## 5. 状态、异常与恢复边界

- 手动暂停/恢复、自动拉黑、Key×模型限制和 quota group×模型限制是不同状态，不得用一个布尔值互相覆盖。
- 自动定时恢复在 UTC 每日 00:00:01、08:00:01、16:00:01 扫描六类渠道；`disabled` 渠道跳过，Key×模型到期限制独立清理。
- 整 Key 只恢复允许自动恢复的原因，并尊重显式 `recoverAt`；无该时间时，禁用不足 1 小时不恢复。满足条件且渠道因无 Key 而 suspended 时可重新激活并转 half-open。
- `scheduled_recovery_state.json` 保存最近检查点。启动或分钟级兜底发现错过槽位时补跑最近槽位；本轮失败保留旧检查点以便重试，不能提前报告成功。
- 手动 Resume 只恢复其职责范围内的渠道和运行状态，不应复活人工删除、明确排除的站点分组或仍处永久限制的对象。
- 所有候选不可用必须返回可诊断原因；degraded 兜底不是绕过 `failedChannels`、硬模型约束或显式指定渠道的理由。
- 配置重载不丢失现有限速 cooldown；后台恢复、指标写入或观测失败不得直接中断正常代理，但必须留下日志和诊断。
- 回滚配置时同时考虑渠道状态、禁用 Key、策略和持久指标；仅替换二进制不代表运行状态已回滚。

## 6. 验收标准

| 场景                           | 必须结果                                                              |
| ------------------------------ | --------------------------------------------------------------------- |
| 前缀、模型、上下文和 X-Channel | 硬约束依次生效，显式渠道不能绕过，错误说明具体不合格原因。            |
| priority、Promotion、亲和      | 数字小者先选；Promotion 只影响普通池；普通亲和可被更优健康渠道覆盖。  |
| 显式模型 fallback              | 主模型穷尽后才到备用；所有尝试共享次数/时间，第三把超限 Key 不发送。  |
| 同渠换 Key/URL 与跨渠道        | 每次正文按当前尝试独立构造，渠道身份、尝试数和失败原因记录准确。      |
| 熔断与关闭开关                 | open→half-open→closed/open 正确；关闭自动熔断后鉴权/余额/限速仍拦截。 |
| 限流水位与响应头               | 50%/30%+5 分钟状态正确，冷却不缩短且最长 1 小时，取消排队及时退出。   |
| 提交后断流和取消               | 不拼流、不继续重试，终态不被误记成功。                                |
| 定时恢复                       | 三个 UTC 槽位、错过补跑、recoverAt、最小 1 小时和失败检查点行为正确。 |

调度测试至少同时覆盖四文本 HTTP、Responses WS、Images 和 Vectors 的共用边界，使用可控时钟及本地假上游验证真实发送次数。
